# Intelligence Hub 产品需求

> 状态：MVP Draft  
> 项目性质：个人项目  
> 更新日期：2026-08-13

## 1. 项目定位

Intelligence Hub 是一个参考 ChatGPT Web 交互方式的 Agent Hub。第一阶段只验证两件事：

1. 能否做出顺手的多轮对话体验。
2. 能否在同一个界面中选择 Agent，并得到可查看、可下载的结果。

它不是面向生产环境的企业平台。MVP 优先保证主流程可演示、代码易理解和功能可迭代，不追求完整的权限、运维和评测体系。

## 2. 目标用户与使用场景

MVP 默认服务于项目开发者本人，暂不设计多人协作。

核心场景：

- 像使用 ChatGPT 一样创建会话并进行流式对话。
- 自动整理会话标题、搜索历史会话，并通过推荐问题继续对话。
- 上传资料后针对文件提问。
- 在需要最新信息时调用联网搜索。
- 管理和调用自己的 Skill，并让系统记住可控的长期信息。
- 从 Agent Hub 选择图片、演示文稿或深度研究 Agent 完成任务。
- 在对话中查看 Agent 进度，并预览或下载产物。

## 3. MVP 范围

### 3.1 对话体验

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| CHAT-01 | 会话管理 | 可新建、切换、重命名和删除会话，刷新后仍保留 |
| CHAT-02 | 多轮对话 | 支持 Markdown、代码块和流式输出 |
| CHAT-03 | 消息操作 | 支持停止生成、重新生成和复制回答 |
| CHAT-04 | Chat/Work 模式 | 新建时选择 Chat 或 Work，首条消息发送后才命名并创建会话；创建后不可切换，两种会话显示在同一列表中；Work 必须选择一个 Agent，并以产出 Artifact 为任务完成标准 |
| CHAT-05 | 执行过程展示 | 在消息中流式展示思考内容和工具调用；可折叠查看工具状态、耗时、参数与结果摘要 |
| CHAT-06 | 自动标题 | 首轮回答完成后自动生成简短标题；用户手动改名后不再自动覆盖 |
| CHAT-07 | 推荐问题 | 每条已完成回答末尾显示一个上下文相关问题；点击只填入输入框，不自动发送 |
| CHAT-08 | 会话搜索 | 可按标题和消息正文搜索，并跳转到对应会话 |

执行过程展示规则：

- 思考区域展示模型接口明确返回的 reasoning/thinking 内容；没有返回时不补写或伪造。
- 思考内容与最终回答分区显示，生成时自动展开，完成后允许折叠。
- 工具调用依次展示工具名称、状态、耗时、参数摘要和结果摘要；状态至少包含准备、执行、成功和失败。
- 不展示 API Key、认证头、系统提示词、完整内部状态或可能包含敏感信息的原始工具载荷。

标题、推荐问题和搜索规则：

- 标题和推荐问题由当前文本模型生成；标题失败时保留默认标题，推荐问题失败时使用与当前主题相关的安全兜底问题，两者都不阻塞主回答。
- 推荐问题作为独立内容块持久化，并始终位于回答、来源和产物信息之后。
- 会话搜索首版使用关键词匹配，结果显示标题、命中摘要和最后更新时间。

### 3.2 文件与联网

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FILE-01 | 文件上传 | 首版支持 `txt`、`md`、`pdf`、`docx`、`png`、`jpg`、`jpeg`、`webp`，显示上传和处理状态 |
| FILE-02 | 文档问答 | `txt`、`md`、`pdf`、`docx` 的短文本直接加入上下文，长文本分块检索；回答标注文件来源 |
| FILE-03 | 图片理解与引用 | 上传图片可用于 Chat 看图问答，也可作为图片 Agent 的参考图；回答或运行记录显示所用图片 |
| WEB-01 | 联网搜索 | 用户明确要求搜索时调用 Tavily，并在回答中列出真实来源链接 |

文件首版限制：单文件不超过 20 MB，单条消息或 Work 任务最多 3 个文件。文档解析失败、图片校验失败或模型无法读取图片时，允许移除或重试。MVP 直接以多模态输入理解图片，不将图片 OCR 后加入文本向量检索。

### 3.3 Agent Hub

Work 模式以产出一个 Artifact（产物）为目标。用户提交任务后，系统通过所选 Agent 执行必要的步骤，并在运行结束时登记一个可查看、可下载的最终产物；阶段进度、思考内容和工具调用属于过程信息。产物类型可以是图片、带引用的研究报告或 PPT/PPTX 演示文稿。

Agent Hub 首版提供三个内置 Agent：

| Agent | 输入 | 输出 | 首版边界 |
| --- | --- | --- | --- |
| 图片生成 | 描述，可选参考图 | 图片预览与下载 | 不做复杂画布编辑 |
| 演示文稿 | 新建需求，或已有演示及修改要求 | 可预览、修改、恢复和下载的 PPTX | 支持 `CREATE`、`MODIFY`、`RESUME` 三种入口 |
| 深度研究 | 研究问题与可选约束 | 带引用的 Markdown 报告 | 限制搜索轮数和总耗时 |

通用要求：

- Agent 只能从 Work 模式启动。
- Chat 和 Work 不能共用会话 ID、历史上下文或会话文件。
- 界面流式展示模型接口返回的思考内容、Agent 阶段进度和工具调用过程，并与最终结果清楚区分。
- 产物与会话绑定，刷新后仍可查看和下载。
- 失败时提供可理解的原因和重试入口。

演示文稿 Agent 额外要求：

- `CREATE`：根据主题生成大纲，用户确认后再生成 PPTX。
- `MODIFY`：基于指定的演示版本和修改要求生成新版本，未指定的页面或内容尽量保持不变，原版本仍可下载。
- `RESUME`：每个主要阶段完成后保存检查点；运行中断或失败后，可从最近检查点继续，已完成阶段和产物不得重复生成。
- MVP 只保证修改本系统生成的 PPTX；上传并编辑任意外部 PPTX 留到后续。

### 3.4 Skill 管理

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| SKILL-01 | Skill CRUD | 可创建、查看、编辑、启用、停用和删除 Skill |
| SKILL-02 | Skill 内容 | 每个 Skill 包含名称、描述和指令，名称不可重复 |
| SKILL-03 | Skill 调用 | 输入 `@` 可选择已启用 Skill；系统也可按名称和描述选择至多一个 Skill |
| SKILL-04 | 调用可见性 | 消息显示本轮使用的 Skill；停用后不能用于新消息 |

通过输入框下方选择器选中的 Skill 属于显式调用，会直接加入 System Prompt；Chat 与 Work 均可同时选择多个 Skill，但 Agent 只能选择一个。未显式选择时，系统也可根据任务自动匹配一个已启用的 Skill；`@Skill` 只作为普通文本。发送时保存 Skill 内容快照，之后编辑 Skill 不改变历史消息。

### 3.5 Memory 管理

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| MEMORY-01 | 用户记忆摘要 | 可查看、编辑和清空唯一的用户记忆摘要，并显示最近更新来源与时间 |
| MEMORY-02 | 启停 | Memory 默认开启；关闭后不提炼、不写入，也不注入模型上下文 |
| MEMORY-03 | 对话控制 | 用户明确说“记住”或“忘记”时执行对应变更并给出回执 |
| MEMORY-04 | 自动提炼 | 会话闲置 6 小时后进入用户待处理队列；每天用户本地午夜统一从队列中的新增消息提炼稳定、低风险的偏好与背景信息 |
| MEMORY-05 | 记忆摘要使用 | Chat 每轮将整份用户记忆摘要注入 System Prompt，Work 复用同一摘要；清空后下一轮立即失效 |
| MEMORY-06 | 记忆对话 | 用户可在 Memory 页与摘要对话；自然语言新增、纠正或删除信息后，唯一摘要同步更新并给出回执 |
| MEMORY-07 | 手动更新 | 用户点击“更新记忆”后，立即处理尚未经过提炼游标的历史消息并更新摘要；同一批消息不会重复处理 |

系统不自动保存密码、密钥、支付信息或其他高敏感内容。自动提炼会更新唯一摘要并记录最近来源会话；重复内容合并，存在冲突或歧义时不自动覆盖。

### 3.6 设置

设置页包含 Skill、Memory、模型服务状态、Tavily 开关和基础外观选项。API Key 通过服务端环境变量配置，不在浏览器中展示。

## 4. 后续候选

以下能力有价值，但不阻塞 MVP：

- `pptx`、`csv`、`xlsx` 等更多文件格式，以及图片 OCR 与图片内容向量检索。
- 消息分支、高级搜索过滤和多个推荐问题。
- 上传并编辑任意外部 PPTX，以及更多 Agent。
- 登录、多用户隔离、团队空间与计费。
- 完整的离线评测、审计、告警、灾备和高可用部署。

## 5. 非目标

MVP 不包含：

- 复刻 ChatGPT 的全部功能或视觉细节。
- 企业级账号、组织与权限系统。
- 第三方 Agent、Skill 或 MCP 市场。
- 移动原生客户端、实时语音和多人协作。
- 任意代码执行或通用沙箱。
- 严格 SLA、跨地域部署和大规模并发。

## 6. 技术约束

- 前端：Vue 3、TypeScript、Vite、Vue Router、Pinia。
- 后端：Python、FastAPI。
- 普通 Chat 使用 LangChain。
- 图片 Agent 使用 LangChain，以结构化图片需求和受控图片工具调用完成生成，不要求 LangGraph 检查点。
- 演示 Agent 使用 LangGraph 编排阶段、确认、版本和恢复，并在图节点内使用 LangChain 调用模型和生成结构化内容。
- 研究 Agent 使用外层 LangGraph 管理运行边界，并嵌入 Deep Agents 完成研究规划、搜索、证据整理和报告草拟。
- 模型统一从阿里云百炼接入，包括支持图片输入的多模态模型；具体模型 ID 由环境配置，不在业务代码中写死。
- 联网使用 Tavily MCP。
- 会话和运行状态保存在数据库；上传文件和产物保存在本地存储或 MinIO。
- 密钥只存在于服务端环境变量或 Secret 配置中。

## 7. MVP 验收场景

满足以下场景即可认为 MVP 完成：

1. 新建会话并连续提问两轮，回答能够流式展示，刷新后消息仍存在。
2. 停止一次生成并重新生成，页面状态正确且不会重复用户消息。
3. 分别上传一个 `docx` 和一张支持格式的图片，能够围绕文档和图片提问并看到对应文件来源。
4. 明确要求联网搜索，回答包含可打开的来源；未要求时不会自动搜索。
5. 在 Work 模式分别启动三个 Agent，Chat 模式不能误启动 Agent。
6. 图片 Agent 可使用上传图片作为参考图，并返回可预览、可下载的图片。
7. 演示 Agent 在确认大纲后返回可打开的 PPTX；能够基于已有版本做定向修改，并从中断任务的最近检查点恢复。
8. 研究 Agent 返回结构清晰、引用可访问的 Markdown 报告。
9. Agent 执行失败时能看到错误并重试，已有会话不受影响。
10. Chat 和 Work 执行时能查看可折叠的思考过程及工具调用详情，刷新后仍能恢复其顺序和状态。
11. 首轮回答后自动生成标题；可搜索标题或消息并打开对应会话；已完成回答末尾有可点击的推荐问题。
12. 创建并启用一个 Skill 后，可通过输入框下方的 Skill 选择器显式使用，也可由系统根据任务自动匹配；Chat 与 Work 均支持显式多选 Skill，停用后新消息不再使用它。
13. 可在设置中管理用户记忆摘要；对话中的“记住/忘记”立即生效，更新后的摘要用于下一轮回答。
14. 会话闲置 6 小时后进入待处理队列，并在用户本地午夜统一提炼符合规则的记忆；关闭 Memory 时不会入队、处理或使用新记忆。

## 8. 完成标准

- 上述验收场景通过。
- 主流程没有阻断性错误，密钥未进入前端或日志。
- 核心模块有基础单元测试，关键流程有最少一组端到端测试。
- 本地启动步骤、环境变量和已知限制有说明。
